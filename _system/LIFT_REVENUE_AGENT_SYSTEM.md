## Why the Human Voice QA agent is different from the rest of this table

Every other agent above either touches a connector (Gmail, Sheets) or feeds a sales-taste decision, which is why most rows sit behind a proof gate. The Human Voice QA agent reads text and suggests edits to text — nothing it does can send an email, write a sheet, or fabricate a business fact (it isn't allowed to invent the specific detail it says is missing; it can only flag the absence). That makes it the one agent in this entire roster with no live-system blast radius at all, and it directly serves the concern that prompted its creation: Megan is worried about output *sounding* AI-generated, and this agent's entire job is catching exactly that before anything ships. Recommend building it ahead of most of the month-2/month-3 roster above.

## Orchestration pattern (unchanged)

Loop L4 (manual): Megan picks prospect → audit agents produce findings (chat) → Asset Verification + Visual QA gates → **Human Voice QA pass on every written deliverable** → Outreach Personalization produces the packet → Megan approves + sends → later: Pipeline Manager / reconciliation agents report sent-vs-tracker → Megan approves tracker writes. No agent hands off to another agent through code; the human is the bus. Fable/Opus re-enters only to design a security-boundary change (the fail-closed web app patch, or the reconciliation write-path gate) — never for routine weekly agent operation.
